# 120面体サイコロの目の配置

このアプリで使っている120面体サイコロ（d120）の目の並びを記録する。実物のサイコロを撮影して起こしたもので、出目ヒートマップ（`/stats/d120`）の3D表示はこのデータに基づく。

## 形状

d120 は **disdyakis triacontahedron**（斜方二十・十二面体の双対）で、120枚の不等辺三角形からなる。頂点は3種類ある。

| 種別 | 集まる面の数 | 個数 | 中心からの距離 |
| ---- | ------------ | ---- | -------------- |
| A    | 10           | 12   | 1.08573        |
| B    | 6            | 20   | 1.01841        |
| C    | 4            | 30   | 1.00000        |

距離の比は、双対元である辺長1の斜方二十・十二面体の各面までの距離の逆数から決まる。外接半径の2乗を `R² = (31 + 12√5) / 4` として、十角形面が `√(R² − φ²)`、六角形面が `√(R² − 1)`、正方形面が `√(R² − 1/2)`。この逆数を最小値で正規化した値が上表になる。

## ロゼット

**各面はA頂点をちょうど1つ持つ。** そのため120面は「A頂点まわりの10面」12組にきれいに分割される。この10面のまとまりをここでは**ロゼット**と呼ぶ。

ロゼットは配置を扱ううえで基本単位になる。

- 各ロゼットは他の5つのロゼットと隣接する（正二十面体の頂点の次数と同じ）
- 各面は、A頂点を含まない辺の向こう側でちょうど1つだけ別ロゼットの面と接する
- 対面ロゼットどうしは決して隣接しない
- 基準ロゼットが同じ隣に渡す境界辺は2本で、その2面は隣側の巡回順でも隣り合う

## 2つの不変量

実物のサイコロは次の2つを満たすよう設計されている。データもこれを満たす。

```
対面の和           = 121
各ロゼット10面の和 = 605
```

対面の和が121なので、1〜120は60組の対面ペアに分かれる。

ロゼットの和605は「1〜120の平均 60.5 × 10面」に等しく、どの頂点まわりを見ても偏りがないことを意味する。

## 向きが紛らわしい目のドット

上下逆さまにすると別の数に読めてしまう目には、数字の**左下**にドットを打って向きを示す。

対象は「各桁が 6・8・9 のみで構成され」かつ「180度回すと 1〜120 の別の数になる」目に限る。1 が入っていれば向きが分かるので除外する。

```
6  9  66  68  86  89  98  99
```

`8` `88` `69` `96` は回しても同じ数に読めるため曖昧さがなく、ドットは打たない。`16` `19` `61` `81` などは 1 で向きが分かるので対象外。

## プログラムから使う

データと幾何はコードに持たせてある。

| 参照先                      | 内容                                                                                        |
| --------------------------- | ------------------------------------------------------------------------------------------- |
| `app/utils/d120Faces.ts`    | `D120_FACE_NUMBERS`（面index → 出目）と `D120_DOTTED_NUMBERS`（ドットを打つ目）             |
| `app/utils/d120Geometry.ts` | `D120_FACES`（頂点・法線・内心・所属ロゼット）と `D120_OPPOSITE`（面index → 対面の面index） |

`D120_FACE_NUMBERS[i]` と `D120_FACES[i]` は同じ面を指す。配置だけが必要なら前者を、3D描画や隣接関係も要るなら後者を併せて参照する。

不変量は `tests/utils/d120.test.ts` で検証している。データを差し替えるときはこのテストが番人になる。

## どうやって起こしたか

実物のサイコロを、12個のA頂点それぞれが正面に来るよう12枚撮影した。全120面がいずれかの写真の中心に写る。

1. 各写真から中心ロゼットの10面を時計回りに読む
2. **合計が605になるか**で読み取りを検算する
3. 12ロゼットが 1〜120 を過不足なく分割するか、各ロゼットの対面が単一のロゼットに収まるかを確認する
4. 1つのロゼットについて、各面の外側で接する目を読む
5. 基準ロゼットを固定 → 対面が確定 → 外側隣接から隣接5ロゼットの位置と回転が確定 → それらの対面5つも確定、で12個すべてが埋まる

### 検算が効いた例

読み取りの誤りは合計605のずれとして現れる。ずれの大きさが回転で入れ替わる目の差と一致したため、いずれも一意に訂正できた。

| 誤読 | 正  | 差  | 根拠      |
| ---- | --- | --- | --------- |
| 99   | 66  | 33  | `99 − 66` |
| 88   | 68  | 20  | `88 − 68` |
| 6    | 9   | 3   | `9 − 6`   |
| 86   | 98  | 12  | `98 − 86` |

いずれもドットが打たれた目、つまり上下の区別が付かない目だった。

外側隣接の読み取りにも誤りがあり、こちらは「基準が同じ隣に渡す2面は、隣側の巡回順でも隣り合う」という構造の制約で検出した。

### 最終的な確認

貼り合わせの解は10通り見つかるが、これは基準ロゼットの回転10通りに対応する。各面とその隣接3面の目の組を並べた回転不変な指紋で数えると、**相異なる配置は1つだけ**だった。つまり配置は一意に定まっている。

加えて、探索に使っていない独立した隣接関係（`111` と `8`、`60` と `58`）が結果として成立することも確認した。
